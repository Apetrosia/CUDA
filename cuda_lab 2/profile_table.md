## Occupancy при размере блока 32

При `T=32` потоков на блок число резидентных блоков на SM оценивается как

`B_res = min(B_max, floor(T_SM/T), floor(R_SM/(R_T*T)), floor(SM_shared/S_block))`.

Здесь `T_SM`, `R_SM`, `B_max`, `SM_shared` берутся из Occupancy Calculator, `R_T` — регистры на поток, `S_block` — shared memory на блок. Для блока из 32 потоков ограничение по потокам обычно очень мягкое; при высокой регистровой нагрузке решающим становится регистровое ограничение.

## Что ожидается от профилирования

1. Простое ядро имеет плохую коалесценцию глобальной памяти: соседние потоки warp работают с разными строками. Поэтому фактическое число транзакций глобальной памяти на получение полезных данных оказывается существенно выше идеального.
2. Быстрое ядро читает одну строку совместно 32 потоками warp, поэтому обращения соседних lanes идут к соседним адресам.
3. В обоих вариантах алгоритмическая интенсивность близка к `0.25 FLOP/Byte`, следовательно верхняя граница по Roofline задается памятью, а не FLOP/s, при типичных дискретных GPU.
4. Если measured bandwidth быстрого варианта заметно вырос, основная причина ускорения — улучшение эффективности глобальной памяти, а не увеличение арифметического объема.
5. Shared memory следует интерпретировать аккуратно: для этого алгоритма данные нельзя широко переиспользовать между разными строками, поэтому она прежде всего обеспечивает локальную редукцию и удобную организацию вычисления. Аналогичного или большего ускорения можно ожидать и от варианта с warp shuffle, если преподаватель разрешает такой подход.
